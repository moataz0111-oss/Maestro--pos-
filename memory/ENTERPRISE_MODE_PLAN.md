# خطة تنفيذ "وضع المؤسسة" — Maestro EGP

**الحالة:** جاهزة للتنفيذ في جلسة جديدة (User confirmed)
**اللغة:** المستخدم يتحدث العربية العراقية فقط

---

## 🎯 المتطلب الأصلي (بكلمات المستخدم):

"لا اريد التعديل ولكن اريد اضافة توسعة للنظام لتحويل المشروع الواحد لمؤسسة يدرها شخص واحد وتكون تدير جميع المشاريع بشكل شامل ودقيق والصفحات تكون تضم اظهار جميع المشاريع وتظهر في هذه الصفحات عند اختيار اي مشروع او فرع من داخل المشروع ولا اريد اي شئ في هذه الصفحات ان يتغير في الديزاين والعمل والالية اريد النظام يعمل بدقة وتلقائيا على ادارة الحسابات واظهار البيانات الدقيقة الفورية والمباشرة"

## 🔒 قاعدة العزل الحديدية (كلمات المستخدم الأخيرة):
"لا اريد اي تدخل من بيانات اي مشروع بالاخر ولا مستخدم اي مشروع للاخر"

**يعني:**
- بيانات مشروع A لا تظهر أبداً في مشروع B (مبيعات، مخزون، موظفين، عملاء، طلبات، تقارير، خزينة، مصاريف، إلخ)
- مستخدم مشروع A لا يستطيع الوصول لمشروع B إطلاقاً (تسجيل دخول، صلاحيات، بيانات، حتى الأسماء)
- المالك فقط (owner المؤسسة) يشوف كل شيء أو يختار مشروعاً معيناً
- التقارير الموحدة على مستوى المؤسسة تظهر للمالك فقط

## 🏗️ خطة التنفيذ (3 مراحل):

### 🟢 المرحلة 1: البنية الأساسية + المعاينة الكاملة
**الهدف:** بناء المعاينة على `/enterprise-preview` بكل الـ 28 صفحة تفاعلية مع البنية الحقيقية

**Backend:**
- Collection جديد: `projects` (id, tenant_id, name, logo, activity_type, currency, timezone, is_active)
- Migration script: كل tenant موجود → مشروع افتراضي واحد
- إضافة `project_id` (Optional) على: branches, employees, products, orders, expenses, warehouses, raw_materials, customers
- `ProjectContext` في FastAPI dependency (يفلتر تلقائياً)
- API جديد: `/api/projects` (CRUD)
- تحديث كل الاستعلامات لتقبل فلتر `project_id` (اختياري، backward compatible)

**Frontend:**
- `ProjectBranchContext` بمستويين
- منسدلة علوية جديدة (مشروع ← فرع)
- شعار واسم المؤسسة/المشروع ديناميكي
- تبويب "المشاريع" جديد في الإعدادات (نسخة من "الفروع")
- Wizard إنشاء مشروع (3 خطوات: نشاط → تفاصيل → إعداد)

**المعاينة:**
- تحديث `/enterprise-preview` لتكون **تفاعلية كاملة** بكل الـ 28 صفحة
- بيانات محاكاة لـ 6 مشاريع (مطعم، صالون، عيادة، سوبرماركت، توزيع، توصيل)
- عند اختيار مشروع → كل الصفحات تتغير ديناميكياً
- شارات العدادات تتغير حسب المشروع
- تقارير موحدة عند "كل المشاريع"

### 🟡 المرحلة 2: نظام العزل والصلاحيات
- Middleware يمنع مستخدم من مشروع من رؤية بيانات مشروع آخر
- دور جديد: `enterprise_owner` (يرى كل المشاريع)
- دور `project_admin` (يدير مشروعاً واحداً فقط)
- `project_manager`, `project_employee` (محدودون بمشروعهم)
- Session token يحمل `project_id` المسموح
- كل استعلام backend يتحقق من project_id في التوكن قبل الإرجاع

### 🔴 المرحلة 3: نشاط "شركة توصيل" (Toters-Style)
- Marketplace: تجار شركاء + عمولات
- Portal للتجار
- تكامل مع نظام السائقين الموجود
- محاسبة العمولات التلقائية

## 🛡️ الأمان والعزل:

### قاعدة عزل البيانات:
```
كل استعلام في backend:
  WHERE tenant_id = current_user.tenant_id
  AND project_id IN current_user.allowed_projects

كل استعلام في frontend:
  يمرر project_id من ProjectBranchContext
```

### قاعدة عزل المستخدمين:
- المالك (enterprise_owner): يرى كل المشاريع
- مدير مشروع: يرى مشروعه فقط
- موظف: يرى مشروعه وفرعه فقط
- لا يوجد رؤية عابرة أبداً
